Problem Statement & Project Objectives

The Corporate Threat

  • Enterprises face targeted ransomware, Active Directory takeovers, and M365 session theft.
  • Powering down servers destroys volatile memory evidence and causes total business shutdown.
  • Average global data breach cost exceeds $4.45 Million.

Our Solution

  • Structured Incident Response Plan aligned with NIST SP 800-61 Rev.2.
  • Automated triage engine with dynamic risk scoring (0-100).
  • Surgical containment without disrupting business continuity.
  • Court-admissible RFC 3227 forensic evidence vault.

Target Corporate SLAs

  • MTTD (Detect): < 5 minutes via EDR/SIEM.
  • MTTC (Contain): < 15 minutes for SEV-1.
  • RTO (Recovery): < 2 hours for critical services.
  • RPO (Data Loss): Zero loss via immutable snapshots.

Corporate IT Threat Landscape & Attack Vectors

Double-Extortion Ransomware

Targets central SAN storage, file servers, and databases. Deletes Volume Shadow Copies, encrypts data, and exfiltrates confidential corporate IP.

Active Directory Takeover

Compromises Tier-0 Domain Controllers via credential dumping (Mimikatz), Kerberoasting, and forging Golden Tickets for persistent administrative control.

M365 Phishing & Session Hijacking

Adversary-in-the-Middle (AiTM) phishing steals OAuth session tokens, bypasses traditional MFA, and establishes hidden forwarding rules on executive mailboxes.

Compromised VPN & Perimeter DDoS

Exploits unpatched remote access SSL-VPN gateways to tunnel into internal subnets or floods corporate single sign-on portals with Layer-7 DDoS traffic.

Playbook A: Corporate Ransomware & Active Directory
Step 1 · Host & VLAN Network Isolation: Apply switch ACLs to quarantine infected subnet. Maintain AC power for memory analysis. DO NOT POWER OFF.
Step 2 · Kerberos KRBTGT Double-Reset: Reset KRBTGT password twice in Active Directory to invalidate all Kerberos Golden and Silver tickets domain-wide.
Step 3 · Volatile Memory Acquisition (RFC 3227): Capture 64GB live RAM bitstream image to write-blocked external storage to extract encryption keys and process footprints.
Step 4 · Validate Immutable WORM Backups: Confirm integrity of air-gapped snapshots prior to infection cut-off timestamp (RPO: 0 data loss).
Step 5 · Provision Clean Gold Master: Deploy sanitized operating system image and replay database transaction journals to restore operations (RTO: < 2 hours).

Playbooks B & C: M365 Email & Perimeter DDoS

Playbook B: M365 Email & VPN

  • Revoke M365 OAuth Tokens: Force global sign-out and invalidate session cookies via Graph API.
  • Purge Rogue Rules: Delete hidden inbox rules routing emails with keywords 'Invoice' or 'Confidential'.
  • Sever VPN Tunnels: Terminate remote access sessions immediately at perimeter gateway.
  • Step-Up MFA: Mandate FIDO2 hardware token challenge for re-entry.

Playbook C: Perimeter DDoS

  • BGP Route Shift: Divert inbound edge traffic to cloud scrubbing centers (Cloudflare/AWS Shield).
  • Layer-7 Rate Limiting: Enforce 5 req/s threshold on single sign-on (SSO) login portals.
  • Drop Hostile Networks: Drop anonymous proxies, Tor exit nodes, and attacker ASN blocks.
  • Gateway Normalization: Edge load returns to normal baseline within minutes.

Digital Forensics & RFC 3227 Order of Volatility
1. CPU Registers & Cache: Most volatile; lost immediately on power cut. Capture first.
2. Physical RAM / Memory: Holds active ransomware keys, plaintext credentials, and injected beacons.
3. Network Sockets & ARP: Captures live C2 connections, established pivot tunnels, and routing tables.
4. Process Tables & Kernel: Running process trees, thread state, and DLL injections.
5. Non-Volatile Disks (SAN): Persistent registry run keys, encrypted files, and local event logs.
6. Remote SIEM Telemetry: Centralized firewall logs, NetFlow, and multi-host correlation records.

Root Cause Analysis (5-Whys) & Compliance

5-Whys Root Cause Analysis

  • Why 1: File shares encrypted at 14:02 UTC causing business outage.
  • Why 2: Attacker used stolen local admin credentials to pivot laterally from WS-042.
  • Why 3: Workstation WS-042 compromised via spear-phishing macro attachment.
  • Why 4: EDR policy on workstation subnet was in 'Audit-Only' mode.
  • Root Cause: Change management failure during network migration left EDR blocking un-enforced.
